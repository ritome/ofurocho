# お風呂帖 UI改善 設計書（v1）

作成日: 2026-08-11

## 1. 目的とゴール

介護施設の入浴管理アプリ「お風呂帖」を、**業務でとにかく迷わない**画面に作り直す。

北極星: 「1秒でわかる・タップを増やさない」。

試行運用の前提:
- 平日（月〜金）午前に、1日あたり**約20名**ずつ入浴。
- 全利用者は**49名**。時々、短期入所者が1〜2名追加される。
- タブレットで使用（未検証。横向き利用を想定）。

## 2. スコープ

### v1（今回作る）
1. 描画復旧・キャッシュ更新（既に着手済みの修正を確定）
2. バックアップ日数バグ（41666日問題）の修正
3. 一覧レイアウトの刷新（行リスト＋タブレット2列）
4. ユニット別グループ分け（すみれ／すずらん／しおん…）
5. 操作フロー（済・取消・未実施理由）の見直し
6. 見た目（男女色分け・未浴・済の視覚言語）
7. 皮膚評価バッジ（印のみ）
8. 皮膚評価一覧（主治医別）の印刷
9. JSONバックアップの確実化＋Excel分析用エクスポート（基本）

### v2以降（今回はやらない）
- 入浴の開始/終了時刻＋所要時間の記録
- 皮膚評価の**結果記録**（異常なし／発赤あり 等）とその一覧・分析
- 利用者属性（体重・介助度など）と所要時間の相関分析
- Excel分析シートの拡張
- クラウドDB（Supabase等）への移行

データ互換ルール（厳守）: 新項目は初期値つきで追加。古いバックアップを読んでも壊れない。既存項目は削除しない。

## 3. データモデルの変更

既存の residents / staff / bathPlans / sessionTeams / settings を維持しつつ、以下を追加する。

### resident に追加する項目
| 項目 | 型 | 初期値 | 用途 |
|------|----|--------|------|
| `ユニット` | string | `""` | グループ分けの見出し（例: すみれ）。未設定は「その他」に集約 |
| `皮膚評価要` | boolean | `false` | true の行にオレンジ「皮膚」バッジを表示 |
| `主治医` | string | `""` | 名前のみ。皮膚評価一覧の主治医別グループに使用 |

### 「今日の対象」の扱い
- 当日入浴する約20名を「今日の対象」として抽出する。
- 抽出方法は既存の bathPlans（当日の予定）に準拠。予定がある利用者＝今日の対象として一覧に出す。
- 短期入所者も、当日の対象に加えれば同じ一覧に混ざって表示される。

## 4. 一覧レイアウト

### 基本 = 行リスト（1名1行）
- 1名を横1行で表示。行のどこでもタップ＝「済」。
- 行の構成（左→右）: 男女の色帯 / 氏名（19px 太字）/ 最終入浴 or 記録時刻 / 空き / バッジ類 / 状態。
- 男女: 左の色帯。男=青 `#9cc0f5`、女=紫 `#c3a9ef`。
- 未浴: 左の色帯を赤 `#d9534f` にし、赤バッジ「N日未浴」`#fdeceb`/`#b02a1f`。
- 済: 緑バッジ「✓ 済」`#2e9e5b`。行はうっすら緑背景。
- 皮膚評価要: オレンジバッジ「皮膚」`#fff4e5`/`#b26b00`（枠 `#f0c98a`）。未浴・済と同時表示可。

### タブレット横向き = 自動2列
- 画面幅が広いとき（横向き想定）、同じ行デザインを**2列**に自動で広げる。
- 約20名がほぼスクロールなしで一望できることを目標にする。
- 縦向き/狭い画面では1列に戻る（レスポンシブ）。

### ユニット別グループ
- ユニット名（すみれ→すずらん→しおん…）で自動グループ化。並び順は設定で変更可能。
- グループ見出しに進捗を表示: 「2 / 4 済」＋横バー。
- 全体ヘッダーに「今日の対象 20名中 7名済 / 残り13名」＋進捗バー。

## 5. 操作フロー

### 済にする / 取り消す
- 行のどこでもタップ＝「済」。
- 戻すときは、行の右に出る「**取消**」だけで戻す。**行タップでは戻らない**（誤操作防止）。

### 未実施（理由記録）
- 各行の右端に小さな「**未実施**」ボタン（グレー枠のピル）。
- 押すと理由リストのポップアップ:
  1. **時間が足りなかった**（先頭・ハイライト）
  2. 本人の希望で見送り
  3. 体調不良
  4. 受診・外出
  5. 拒否
  6. その他
  - ＋メモ欄（任意）
- 理由の並び順・文言は設定で変更可能にする。
- 未実施を記録した行はグレー表示にし、「未実施・{理由}」を短く表示。取り消しは右の「取消」。

## 6. 皮膚評価

### 表示（v1）
- 利用者設定に「皮膚評価が必要」チェックを追加。
- チェックが付いた利用者の行に、オレンジ「皮膚」バッジを表示（印のみ。結果は記録しない）。

### 皮膚評価一覧（主治医別）＋印刷
- 「皮膚評価が必要」な利用者だけを抽出し、**主治医名でグループ化**した一覧画面を用意する。
- 表の列: 部屋（ユニット）/ 氏名 / 最終入浴 / **所見（空欄の記入欄）**。
- 主治医は**名前のみ**の項目。並び順は主治医名でまとめる。
- 印刷: ブラウザ標準の印刷（`window.print()`）＋印刷用CSS。追加費用なし、A4想定。
- 所見のアプリ内記録は v2 で追加可能（今回は空欄）。

## 7. 既存不具合の修正

### 描画復旧（着手済み・確定する）
- `@babel/standalone` をバージョン固定（`@7.24.7`）。
- Babel presets を `react` のみに（`env` を外す）。
- Service Worker の `CACHE_NAME` を `ofurocho-v3` に更新し、旧キャッシュを破棄。

### バックアップ日数バグ（41666日問題）
- `lastBackup` 未設定時にエポック起点で日数計算してしまい「41666日」等の異常表示になる不具合を修正。
- 未設定時は「まだバックアップしていない」旨を表示し、異常な日数を出さない。

## 8. バックアップ / データ活用

- データはローカル（localStorage）に保持（クラウド移行はv2以降）。
- JSONバックアップを確実に取り出せるようにする（エクスポート導線の明確化）。
- Excelでの分析・閲覧用エクスポート（基本）を用意する。Excelは**閲覧・分析のみ**（アプリへの取り込みは想定しない）。
- 詳細な分析シート拡張・相関分析は v2。

## 9. テスト観点

- 描画: 主要画面が空白にならず表示されること（コンソールエラー0）。
- 互換: 旧バックアップJSONを読み込んでもクラッシュしないこと。新項目に初期値が入ること。
- 一覧: 20名規模でユニット別に正しくグループ化・進捗集計されること。
- 操作: タップ＝済、取消のみで戻る、未実施→理由記録→グレー表示、が意図通り動くこと。
- タブレット: 横向きで2列、縦向き/狭幅で1列になること。
- 皮膚: バッジ表示、主治医別一覧の抽出・グループ化、印刷レイアウトが崩れないこと。
- バックアップ: 41666日等の異常表示が出ないこと。JSON/Excelエクスポートが取得できること。
